Design system

Table filters

DTFilters — the search + period bar of a data table, in DTToolbar's filters zone. One component, two commit models. Status tabs sit above the table, outside this bar, and always apply at once.

01mode="apply"

The controls edit a draft; the table changes only on Apply filters or Enter. Use it for large or server-side lists, where each change costs a request.

02mode="live"

No second row: the period and the scope apply at once, the text after a 250ms debounce. Pills are optional (showPills); they sit in the same second row as apply mode and their ✕ removes now. Use it for small local lists, where filtering is free.

Live, with pills

Same second row under the same hairline, holding only the pills — nothing to apply, so no Apply or Clear. The ✕ removes now.

03Sort control

Sort sits in the toolbar actions, first in the order Sort · Expand/Collapse · exports. It is a Combobox with an icon-only trigger: the glyph is the order in use, the list carries the text.

Open

Combobox size="sm" iconOnly align="end", every option with an icon. The label stays in the trigger as sr-only, so it is announced as "Sort: Date, newest first".

04Rules

PartRule
ScopesConfigured per screen (scopes). Picking one opens the field with a width animation and focuses it; picking it again closes it and clears the text.
Value scopeinputMode="decimal", and filter with matchesDigits: "40095", "40,095.00" and "40.095,00" all find the same amount.
PeriodDateRangePicker size="sm", portaled — a .dt-wrap clips overflow.
Enter (apply)Applies from the field, the date trigger or with nothing focused. Buttons and pills keep their own Enter.
Order of the second rowApply · Clear filters · a vertical rule · the applied pills. Items enter and leave in 180ms with a 6px slide.
AccessibilityScope buttons use aria-pressed; the closed field is aria-hidden and out of the tab order; every pill action has a label. Motion respects prefers-reduced-motion.
