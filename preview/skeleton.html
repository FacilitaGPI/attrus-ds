Skeleton

A placeholder for content that is loading, in three shapes — a text line, a circle and a rectangle — for cards and lists. The one rule: build it in the shape of what is coming, so nothing moves when the data lands. The table's .dt-skeleton uses the same shimmer.

API

<Skeleton shape="text"   width="70%" />        // one line; its height comes from the parent font
<Skeleton shape="text"   lines={3} />          // a paragraph; the last line ends short
<Skeleton shape="circle" size={32} />          // avatar, icon
<Skeleton shape="rect"   width={120} height={32} />  // button, image, chart

<SkeletonGroup label="Loading transactions">   // role=status, aria-busy and a screen-reader label
  …
</SkeletonGroup>

Skeleton beside the real content

Switch between the two: neither the card nor the list changes height or position when the data lands. How: each text line takes the height of a real line (the bar is the x-height, the rest is margin), and the number of lines is that of the typical content — here, a two-line paragraph.

Rules

Match the content. One text line per real line, at the font size the text will use; the same avatar size; the same button size. If the content is usually two lines, draw two.

Announce once. Wrap the loading region in SkeletonGroup label="Loading …": it is a status with aria-busy, and the shapes inside are hidden from assistive tech.

When not to use. For a wait under about 300ms show nothing; for an action the user started (a save, a payment) use the button's loading state; for a full-page first load the skeleton is right.
