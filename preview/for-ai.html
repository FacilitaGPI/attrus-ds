Design system

For AI · Usage rules

Read this first when consuming ATTRUS. The design system already ships a canonical component and token for nearly every UI need — the golden rule is reuse before you recreate. Each component's doc page carries an API & usage panel (and a machine-readable #ds-api JSON block) with its variants, props and preferred usage.

Golden rules

1

Prefer the canonical component

Before building any UI, check if the DS has it. Use ATTRUS.<Component> (React) or the canonical class (e.g. .btn, .stepper). Never re-implement a button, pill, table, stepper, modal, drawer or combobox from scratch.

2

Consume tokens, never raw values

Colors, spacing, radius, shadows, type — always var(--token). Never hardcode hex, px for spacing/radius, or font stacks. Raw literals break theming (light/dark) and the product axis (Enterprise/Business).

3

One theme surface, two axes

data-theme = light/dark (surface + intensity); data-product = brand matiz. Both live on <html>. Don't redefine surface/feedback tokens per product — only the brand/accent/gradient/shape surface.

4

Read the API panel, not the prose

Each doc page's #ds-api JSON is the source of truth for variants and props (generated from the .d.ts). Match those exact names.
