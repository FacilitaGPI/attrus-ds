01Intent

A global command palette. It searches across the product — counterparties, transactions, accounts, actions — and takes over the screen while open. It does not fill a field.

Use when

All three hold: the user is navigating rather than entering data; the search spans more than one entity type; and the entry point is global — a keyboard shortcut or a persistent search affordance, not a control inside a form.

Use instead

WhenUse
The choice writes into a fieldCombobox — the palette portals over the page and takes focus, which would cover the very input being filled.
Filtering a table already on screenThe table's own search — a palette that replaces the view loses the context the user is filtering.
One entity type, short listCombobox or a native select. A palette for eight known options is ceremony.
Free text the user is composingInput. The palette commits a destination, not a value.

Context

The palette is the product's answer to "I know what I want, I do not know where it lives." It is opened by ⌘K from anywhere, so it must assume no surrounding layout — it floats, dims what is behind it, and returns the user to where they were. Because it is reachable at all times, it is also the component most likely to be opened by accident: the inactive and empty states carry as much weight as the results state.

03Anatomy

One input and a stack of optional blocks. The eight states in §02 are not eight components — they are this structure with different blocks present.

PartRole
.ssRoot panel. Caps at 380px — a comfortable reading measure, narrow enough not to blanket the page behind it.
.ss-input · .ss-input-flatThe query row. -flat drops the border for when the palette sits inside a framed surface.
.ss-clear · .ss-kbdClear affordance and the shortcut label. The kbd is a label — it does not bind the key.
.ss-section · .ss-section-labelGrouping unit. Every block below is a section.
.ss-chips · .ss-chipSuggested actions — the "you can also do this" row.
.ss-result-label"RESULTS (N)" line. The count is the consumer's to compute.
.ss-list · .ss-list-itemResult rows. The row is the control.
.ss-recentSection modifier for history — leading icons shrink to bare glyphs so past searches read below live results instead of competing with them.
.ss-no-resultEmpty line naming the failed term. Emitted by the emptyQuery prop.
.ss-hintTip card — ID format help, or a "did you mean" suggestion.
.ss-typebtns · .ss-typebtnType filters shown when a query is ambiguous.
.ss-illoIllustration block for empty and error states.
.ss-skeleton and -row · -circle · -bar · -bars · -shimmerLoading placeholder. Fixed at three rows — the same height a loaded list occupies, so the panel does not jump when results arrive.
.ss-footKeyboard legend strip.

04Variants & composition

The palette has no size or tone variants — it is one shape. What varies is which blocks are present, and that is driven by props rather than modifier classes.

PropRenders
chipsSuggested-action row. Use for the two or three things people do most, not a menu.
sections + variant: 'recent'Result groups; the recent variant styles history more quietly.
resultLabelThe count line above the list.
emptyQueryThe no-result line, with the term emphasised.
hintTip card — pair with typeButtons when a query is ambiguous.
typeButtonsType filters. Only useful when the query genuinely matches more than one entity.
empty · error · loadingThe three non-result states. They are mutually exclusive: loading wins, then error, then empty.
flatDrops the panel border for use inside an already-framed surface.
Composition rule: the palette owns the whole screen while open, so it composes with nothing. Do not place it inside a Drawer, a Modal or a table cell — if it needs to live inside another surface, the component you want is Combobox.

05For agents

The palette is the most tempting component to misuse, because a search field looks like a search field. What separates it from a Combobox is scope: this one owns the whole product and takes over the screen to do it.

Use when

All three must hold.

Intent
The target could be anywhereA record, a screen, a command. If the answer is always in one field, that is a Combobox.
Typing beats navigatingThe user knows the name or the ID. A palette rewards intent; it does not help discovery.
Results span entity typesCounterparties, transactions, settings in one list. A single type is better served by a filtered list.

Use instead

Precedence
SituationComponent
The choice fills a form fieldCombobox
Fewer than 5 fixed optionsnative select
Filtering a list already on screenSearchPill + ToggleChip
Multi-select of tagsToggleChip

Anti-patterns

Each renders without error.

Avoid
Anti-patternWhy it fails
Using it as a field-level pickerIt portals over the page and takes focus. Inside a form it hides the field the user was filling.
No ⌘K bindingA palette reachable only by clicking an icon is a search box with extra layers. The shortcut is the pattern.
Results from one entity typeThe grouping machinery adds nothing, and the takeover costs the user their context.
Copying the footer chipsThey are captions. Copying them promises keys that nothing listens for — see Behaviour.
Long ungrouped listsPast roughly seven rows the user scans instead of reading. Group, or narrow the query.
Two palettes in one appThe shortcut can only belong to one, so the second is unreachable by the means that defines it.

Rules for agents

Constraints
One palette per applicationIt owns ⌘K globally.
Always bind ⌘K / Ctrl+K and EscOpen and close. Without both the palette is a trap.
Section labels: mono uppercase, one wordThey are signposts, not sentences.
≈7 items per sectionBeyond that, group further.
static only in documentationIt disables the portal, so in production the palette would be trapped by any overflow ancestor.

06Behaviour & contract

The palette carries more unshipped behaviour than any other component here — most of what makes it feel instant is the consumer's job.

Ships in SmartSearch.tsx

Shipped
State composes from propsThe eight states are not a state enum — the component renders whichever slices it receives, in canonical order. Passing hint + typeButtons is the "id" state.
Portals over the pageEscapes any overflow ancestor, the same fix Modal and Drawer needed.
static keeps it inlineSo a doc gallery can show several states side by side without them stacking on the body.

You must implement

Whether you use the CSS or the component.

Your job
⌘K / Ctrl+K and EscThe component does not register global keys — that belongs to the app shell.
Arrow navigation and EnterPlus aria-activedescendant, or a screen reader hears nothing as the selection moves.
Scroll-into-viewOnly when the active item leaves the viewport, or it fights the mouse.
Focus returnSend focus back to the trigger on close, otherwise tab order restarts at the top of the page.
Debounce and loadingQuery timing and when to show loading are yours.

07Presentational only

Four pieces look like controls and are not. Each has been copied at least once in this project on the assumption that the markup carried the behaviour.

ElementWhat it does not do
.ss-kbd chipsLabels. They describe ⌘K, ↵, esc; they bind nothing. The listener is yours.
.ss-typebtnStyling only. Marking one active does not filter — the type filter is the consumer's.
.ss-result-labelA slot. "RESULTS (12)" is a string you compute; the component does not count.
.ss-clearRenders the affordance. Clearing the query and refocusing the input is yours.
