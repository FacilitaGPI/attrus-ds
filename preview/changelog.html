1.0.10

2026-08-18 · the weight scale now matches the typeface

Fixed

  • Three of the seven weight tokens did not exist in Lato. Measured rendered advance: 500 renders identically to 400, 600 identically to 700, and 800 identically to 900. Lato ships Thin / Light / Regular / Bold / Black only — there is no Medium and no SemiBold. Google Fonts accepts the request for them without error and the browser rounds silently, so the scale advertised seven steps while rendering four.
  • The consequence was systemic: --w-semibold was the most used token in the system (99 CSS rules) and rendered bold everywhere, which is why the UI read heavier than the scale implied and why no fine weight hierarchy was possible.
  • Every --w-semibold is now --w-regular — what used to render bold-by-accident is plain text. --w-medium → regular and --w-extrabold → black were visually neutral: they codify what the browser was already doing. Genuine emphasis keeps --w-bold.
  • The @import now requests only weights that exist (300 / 400 / 700 / 900 roman, 400 / 700 italic). It previously asked for 100, which no token declares, and for the three phantom weights.

Changed

  • The scale is now light 300 · regular 400 · bold 700 · black 900 — four real steps. --w-medium, --w-semibold and --w-extrabold are kept as deprecated aliases so a consuming project does not break, but new code must use one of the four.
  • Migrated: 8 declarations in colors_and_type.css, ~100 rules across 22 component stylesheets, and 44 inline weights in the app kit — including the demo toolbar helper in index.html, which sat in a <script type="text/babel"> block and was the last place still rendering the phantom bold. Verified by re-measuring the loaded app: rendered weights are 400 (628 elements) and 700 (20), with the 500 / 600 / 800 band empty.

Notes

  • This surfaced from a much smaller observation — the sidebar items looked bold. They were declared 500 and rendering 400, so lightening them appeared to do nothing; only the section headers (declared 600, rendering 700) visibly changed. That asymmetry was the clue.
  • If a real Medium / SemiBold step is ever needed, it requires a different family — no amount of loading fixes a weight the typeface does not contain.

1.0.9

Patch
2026-08-18 · mono optical size

Added

  • --font-mono-adjust — optical size for the mono family, consumed via font-size-adjust by every rule that sets --font-mono. Set it to none to disable the mechanism entirely, and a product theme may override it alongside --font-mono.

Fixed

  • JetBrains Mono rendered visibly larger than Lato in mixed text. Measured at 200px: mono x-height 0.550 against Lato's 0.5065 — 8.6% taller at the same font-size, while the cap height differs by only 1.9%, which is why the mismatch reads at the x-height. The font is drawn for code editors, where a tall x-height helps; in 10–13px UI labels beside sans text it just looks oversized.
  • All 47 mono rules now carry font-size-adjust: var(--font-mono-adjust), scaling the glyph to Lato's x-height. Measured effect: mono advance −7.9%, sans untouched (font-size-adjust: none).
  • 35 inline mono usages also patched — elements that set fontFamily in JSX/TSX rather than through a canonical class are invisible to a rule-based mechanism, so they kept the old size and produced a fresh mismatch (the topbar's "ENTERPRISE" beside an adjusted Live 0:19). Covered: 27 in the app kit, 2 in SmartSearch, 5 in benches, and 1 in the export/nextjs reference app. Verified across the loaded dashboard: 61 mono elements adjusted, 0 missing; 116 sans elements correctly untouched.
  • The mono type specimen in the docs (.family.mono) is included too — otherwise the page documenting the family would render at the unadjusted size and contradict shipped behaviour.

Notes

  • Three lighter mechanisms were prototyped and rejected. A single font-size-adjust on :root (1 line) normalises every family, and measurement showed it shrinking Lato by 1.3% — a global side effect to fix a local problem, and a silent trap for any product that swaps its sans. A @font-face wrapper with size-adjust (~5 lines, zero rules) forces self-hosting and, worse, cannot be overridden by a product theme, since a theme file can redeclare tokens but not a font src. Replacing the mono family outright fixes today and leaves no mechanism for tomorrow.
  • The 47 rules are a one-time cost: they read the token, so a future font swap is two lines — the family and its calibration.
  • font-size-adjust needs Chrome 127+ / Safari 16.4+ / Firefox. Older engines ignore it and render the previous behaviour, so the failure mode is graceful.

1.0.8

Patch
2026-08-18 · quieter hairlines

Changed

  • Ambient borders are now ink-alpha hairlines instead of fixed neutral steps: --color-border-subtle / -default / -strong read 4% / 7% / 12% of ink in light, and 4% / 6% / 10% white in dark (previously neutral-100/150/200 and white 8/12/20%). Transparency means the line takes the hue of whatever sits under it, so it reads as a seam rather than a rule.
  • Six token values in colors_and_type.css — no component rule, no new token, no TSX change. Everything that reads --color-border-* follows automatically, including the app's inline styles.
  • Semantic borders untouched — focus, accent and the success / warning / danger / info borders stay solid: they carry meaning and must remain legible.

Notes

  • The default hairline sits at ~1.16:1 against a white surface (it was 1.23:1). On a 1× display with a light colour profile it can read as almost absent — if that comes up, raise -default from 7% to 9% rather than reverting the approach.
  • Alpha borders can drop out of some print pipelines. A surface that must print should override the border with a fixed neutral inside @media print.
  • A firmer, separate token for control boundaries (--color-border-control) was prototyped and dropped: at the weight that actually looked right, the field border matched the divider, so the extra token earned nothing.

1.0.7

Feature
2026-08-07 · animated backdrops from the Background Lab exploration

Added

  • AnimatedBackdrop (.abg) — eight full-bleed animated backgrounds for hero, onboarding and marketing: aurora (drifting blobs), mesh (dot mesh that brightens around the cursor), grid (flat grid with glints running the lines), ripple (concentric waves), beams (horizontal trails at mixed speeds), orbits (rings with satellites), apex (the brand mark traced by a light beam) and triangles (oversized drifting planes).
  • Every tint derives from --color-brand-solid / --color-accent-solid, so a backdrop reskins with the active product. The ink base (--abg-ink) flips with the theme, and prefers-reduced-motion disables all motion.
  • .abg-scrim — mandatory readability veil, with .is-vertical for centred copy. .is-tinted layers multiply on light surfaces so a translucent layer over white keeps its hue instead of turning grey.

Changed

  • AmbientBackdrop stays the layer for plain static blobs; reach for AnimatedBackdrop when motion is part of the message. One animated backdrop per screen — two compete with each other.

1.0.6

Patch
2026-08-03 · patch from real consumption (landing page + onboarding flow)

Added

  • SelectableCard (.sel-card) — a card that is a control: pick-one / pick-many with index, description and marker. Replaces the hand-rolled .card + .radio composition that every onboarding and KYC flow reinvented.
  • ToggleChip (.toggle-chip) — selection chip with aria-pressed for multi-select filters and tag pickers. .chip is a removable token and .pill.interactive is a status pill — neither was a form control.
  • ActionBar (.action-bar) — persistent action strip for wizard, drawer and editor, on --glass-chrome. Right cluster aligns with margin-left:auto, never a flex spacer.
  • AmbientBackdrop (.ambient) — the official decorative layer: tokenized radial blobs that follow the active product, a mandatory readability scrim, and prefers-reduced-motion built in.
  • Semantic glass — --glass-surface / -chrome / -overlay / -hero, each with a paired -fg, remapped in dark (-hero stays dark in both themes by design).
  • Display / editorial layer — --fs-9xl (96px), --ls-display-xl, classes .display-hero, .display-hero-xl and .overline-mono.
  • Entrance choreography — --ease-entrance, --duration-entrance, --stagger-tight/base/loose plus .enter / .enter-1..5 utilities respecting reduced motion.
  • Dark-surface focus + glows — --shadow-focus-inverse (the Sky ring vanished over ink) and --shadow-glow-accent / -brand / -success.
  • Breakpoint tokens — --bp-sm/md/lg/xl as the single reference for JS, docs and the token export.
  • On-inverse layer for controls — .switch, .check, .radio, .field and .stepper joined .input, so permanently-dark heroes and onboarding stop overriding colour inline.

Changed

  • --color-brand-text renamed to --color-brand-text-on-light so the name declares its restriction (fixed light background only). The old name stays as a deprecated alias.
  • --glass-white*, --glass-tint and --glass-ink* demoted to raw primitives — they are not theme-aware. Use the semantic glass tokens on themed chrome.
  • README corrected: the selected-state recipe now points at --color-background-selected (the light-only --color-brand-primary-50 broke in dark), and the disabled recipe no longer recommends opacity.
  • Token export regenerated — 372 tokens, 52 dark overrides, 33 categories.

Fixed

  • --color-brand-text broke in dark. The token resolves navy in every theme — 1.05:1 on the ambient surface. Ambient consumers (.btn-link hover/active, .eyebrow-brand, the active sidebar count, combobox selected meta and active filter count, file-list action hover, file icons and pending status) now read the theme-aware --color-foreground-brand. Fixed-light-background consumers keep navy at 15:1.
  • Disabled switch / checkbox / radio used opacity:.5. It composed with the surface into an off-palette tint, erased the white thumb, and made checked+disabled indistinguishable from unchecked+disabled. Replaced with explicit tokens, and cursor:not-allowed moved to the wrapper so the whole hit target reflects the state.
  • Stepper labels overlapped in narrow containers (“AtivaçãoRecebimento”). Root cause: .stepper .step-body carried a fixed max-width: 16ch and overflowed its own flex:1 step on both sides, so the label’s ellipsis never engaged. The body is now bounded to the step, labels truncate, and .stepper.is-wrap opts into two lines.
  • Code chips in the new component docs measured 3.95:1 — below AA — and now use --color-foreground-brand at semibold.

1.0.0

Initial
2026-06-19 · first tagged release

Added

  • Multi-product theming — two orthogonal axes: data-theme (light/dark) × data-product (Enterprise / Business). Theming surface spans color, gradients, inverse layer and shape.
  • Product themes — themes/enterprise.css (Navy) + themes/business.css (Blue), loaded via a single themes/index.css; new product = 1 file + 1 import + 2 registrations. themes/_template.css scaffold included.
  • Product & theme controls — selector + dark-mode toggle in the catalog, app topbar, and both index hubs; persisted, anti-FOUC (theme-toggle.js).
  • TypeScript layer — 20 typed component wrappers (components/*/*.tsx) over the canonical CSS, each with a live bench gallery.
  • Dark mode — full token remap via [data-theme="dark"]; validated across app, catalog and docs.
  • Data-viz tokens, token export (JSON / Style Dictionary), and the drift linter (tools/drift-linter.html) guarding CSS↔TSX↔theming.
  • Index hubs — preview/index.html (example pages) and components/index.html (TSX benches), cross-linked; bench pages get a back-link.
  • This changelog + version.js single-source version, mirrored on the catalog and index pages.

Changed

  • Brand surface tokenized — every component (CSS + TSX + app) consumes --color-brand-* / --color-accent-* instead of raw scales, so a product reskins the whole system with no component edits.
  • Gradients & inverse layer derive from --color-brand-solid — hero backdrops and dark/premium panels follow the active product.
  • Shape tokens (--shape-control/-container/-overlay) pick steps from the radius scale; Business reads rounder than Enterprise.

Fixed

  • Dark-mode contrast — skeletons, the Failed table row, and ~52 raw light-tint usages across components and docs migrated to theme-aware tokens.
  • Stray Royal refs — sidebar active count, combobox chips, file-action hover and focus borders now product-aware.
  • Cache-busting on theme-toggle.js / themes/index.css to avoid stale tabs.
