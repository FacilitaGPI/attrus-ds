Callout

An icon-led note that sets a short message apart from running content — tips, warnings, results, and asides. Tonal variants carry meaning; the tint adapts to the theme.

Prefer a callout for a block-level aside tied to nearby content. For transient feedback after an action use Toast; for a blocking decision use Modal; for emphasis inside a sentence use the accent-text patterns. Never stack two callouts.

01Tones

Five tones, each driven by two custom properties (--callout-tint for the box, --callout-fg for the icon). The background is color-mix'd against the surface, so every tone reskins automatically in dark mode — try the toggle, top-right.

03Anatomy

A leading icon (18px, or 16px when compact) and a .callout-body message. The body takes strong, code, and links; the icon is any Lucide glyph that fits the tone.

Structure

Markup
Defined once in components/callout.css?v=8 and consumed by every doc page and product surface — edit the CSS and all callouts move together. See the catalog.
<!-- info (default) --> <div class="callout"> <i data-lucide="info"></i> <div class="callout-body">Your message, with <strong>emphasis</strong> or <code>tokens</code>.</div> </div> <!-- tonal + compact --> <div class="callout callout-warn callout-sm"> … </div>

04Rich content & actions

Wrap the message in .callout-content to stack a .callout-title, body and an .callout-actions row of buttons. Add a .callout-dismiss button to make it closeable. Buttons are the canonical .btn — use small ones (.btn-xs): .btn-secondary for the action (its border keeps it legible on the tinted box), .btn-ghost for the soft option, and .btn-danger for destructive.

05Alert bar

Add .callout-bar for a full-width banner: items center on one line, a left accent rule aids scanning, and actions/dismiss sit inline-right. Use at the top of a page or section for system-level messages. Add .callout-rounded when it sits inside a padded container rather than edge-to-edge.

06Inline & on-inverse

Two modifiers for tighter contexts. .callout-inline sizes the box to its content on a single line — for hero badges and inline notices, not full-width asides. .on-inverse swaps the light tint for a glassy translucent fill with light text, so a callout reads on a dark hero, photo, or inverse panel (mirrors .pill.on-inverse).

07Usage

A callout interrupts reading — spend it carefully.

Do & don't

Guidance
Do — match the tone to the message: warning for risk, success for confirmation, neutral for incidental notes. One idea per callout.
Don't — stack several callouts in a row, or use danger for anything that isn't an error. If everything is highlighted, nothing is.
For emphasis inside a sentence, use the accent text/highlight patterns instead — a callout is a block, not an inline mark.

08For agents

The decision rules an agent needs before reaching for this component — when it is the right answer, when a different component is, and what will look correct while being wrong.

Use when

All three must hold, or the answer is another component.

Intent
The message is tied to nearby contentIt explains, qualifies or warns about something the reader can see. A message about the whole session belongs in a toast; a message about the whole account belongs in a page-level bar.
It should persistThe reader may need it again after scrolling or a re-render. Anything that should disappear on its own is a Toast.
It does not blockThe reader can ignore it and continue. If the flow must stop until a choice is made, that is a Modal.

Use instead

Four routes away from this component.

Precedence
SituationComponent
Confirmation right after an action, self-dismissingToast
The flow must stop until the reader decidesModal
A field is invalid — the message belongs to that fieldInput error / hint
Emphasis on a phrase inside running textaccent-text / highlight patterns

Anti-patterns

Each of these renders without error, which is why they survive review.

Avoid
Anti-patternWhy it fails
Two or more callouts in sequenceA callout earns attention by being the only interruption. Stacked, they become a list with decorative boxes — and the reader skips all of them.
danger for anything that is not an errorDanger is the strongest tone and also the only one that sets role="alert". Spending it on emphasis means the next real error announces nothing new.
A callout for field validationIt sits away from the field, so the reader has to map the message back to the input. Field-level error text is anchored where the fix happens.
Paragraphs of body copyThe box implies "read this now". If it takes more than two sentences, it is content, not an aside — put it in the page.
Primary buttons in actionsA primary CTA inside a note competes with the page's own primary action. Use secondary or ghost.
bar inside a card or panelThe bar is a full-bleed page-level device: square corners, side borders removed. In a container it reads as a broken card — use rounded if you truly need it there.
Tone chosen for colourTone is semantic and is read by assistive tech through role. Picking success because green fits the layout is a lie to the screen reader.

Rules for agents

Deterministic constraints — safe to apply without judgement.

Constraints
One callout per view regionIf a second is needed, merge the messages or promote one to a page-level bar.
Body copy ≤ 2 sentencesBeyond that, use title for the claim and keep the body short.
actions ≤ 2 buttonsSecondary or ghost only. More than two turns a note into a form.
Always pass iconThe layout reserves the leading slot; without an icon the text hangs on an indent with nothing in it. Use a Lucide glyph matching the tone.
Never set role by handThe component derives it from tone — see Behaviour. Overriding it desynchronises the visual tone from what is announced.
onInverse only on a dark surfaceIt swaps the tint for a glassy translucent fill and light text; on a light surface the text drops out of contrast.
rounded requires barOn its own it does nothing — the default box already has a radius.

09Behaviour & contract

What the component does on its own, and what falls to you when consuming the CSS directly. Copying the markup does not buy the behaviour.

Ships in Callout.tsx

Automatic — do not re-implement.

Shipped
role derived from tonedanger renders role="alert" — assertive, interrupts the screen reader. Every other tone renders role="status" — polite, announced at the next pause. This is the reason tone is semantic and not decorative.
Layout switches on contentPassing title or actions wraps the body in .callout-content (vertical stack). Without them the body renders flat, so a one-line note never pays for the richer structure.
Tone class always emittedEven info, the default — .callout-info is what .on-inverse pairs with in CSS, so omitting it would break the dark treatment.
Dismiss is conditionalThe × button renders only when onDismiss is passed, already labelled aria-label="Dismiss".

CSS only — you must implement

Using the classes without the component.

Your job
role="alert" / role="status"Nothing in the CSS announces anything. A danger callout without role="alert" is invisible to a screen reader.
.callout-icon on the iconThe TSX takes the icon as a slot and expects the caller to carry the class; a bare <svg> gets no sizing or tone colour.
Dismiss wiringThe <button class="callout-dismiss"> needs its own aria-label and click handler, plus whatever removes the node.
Focus after dismissalRemoving the node while focus is inside it drops focus to the document. Move focus to a sensible neighbour first.
