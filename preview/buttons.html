Buttons

Pill-shaped, action-driving controls. Triggers a single, immediate action — submit a form, confirm a destructive change, navigate to a flow. For navigation that should look passive (in-page anchors, footer links), use a plain link.

01Intent

A button commits an action in place. If the click navigates, it is a link; if it holds a value, it is a control. Getting that distinction right removes most of the wrong picks below.

Use when · use instead

The decision is the variant, not the component — nine variants exist so weight matches consequence.

decision
SituationReach for
The one committing action of a view — submit, confirm, sendprimary. One per view: a second splits the decision and neither reads as the point.
A real action that is not the point — cancel, save draft, exportsecondary. Safe to repeat; it does not compete.
Dense toolbar where outlines would stack into a grid of linestertiary — tonal fill, no border.
Action inside a table row or cardghost. A bordered button there competes with the row itself.
Action that sits inside a sentencelink. Still a button semantically — it does not navigate.
Destructive, in a dialogdanger paired with a secondary that cancels. Never the dialog default.
Destructive, at row leveldanger-outline — same meaning, less weight.
On a permanently dark surfaceinverse, or onInverse on any variant.
Icon with no label — toolbar, row actioniconOnly plus aria-label.
2–4 related choices that act as one controlButtonGroup, children sharing one variant.

Not a button

Three cases where a button is the wrong element, whatever it looks like.

boundary
If the click…Use
Changes the URL or opens a document<a>. Style it btn-link if it should read as a link, but the element must be an anchor — middle-click, copy-link and back all depend on it.
Holds an on/off valueSwitch, or a ToggleChip for a filter. A button fires and forgets; it has no state to read back.
Picks one of several valuesCombobox, radio group, or Tabs if it switches a view.

02Anatomy

A button is built from three optional parts inside a pill container. Order is leading icon → label → trailing icon; never break this order. Icons are optional but the label is mandatory unless the button is in .btn-icon mode.

1 Leading icon Reinforces the action's meaning before the label is read.
2 Label Action verb in sentence case. 1–3 words.
3 Trailing icon Hints at progression — arrow, chevron, external link.
4 Pill container radius-pill · ring on focus · 24/32/40/48px tall.

06Composition

Buttons rarely live alone. Three established patterns: action pairs (form footer), toolbars (mixed ghost/secondary), and segmented groups (one logical control split into mutually-exclusive options).

Form footer

Right-aligned. Cancel as Ghost on the left, Primary on the right. Never reverse the order.

Destructive confirmation

Cancel as Ghost. Destructive action solid, focus-ring tinted danger.

Toolbar

Ghost icon-only buttons grouped tightly with secondary text actions for context.

Segmented group .btn-group

One logical control with mutually-exclusive options. Use Secondary as base.

08Don'ts

Common pitfalls. Each undermines the visual hierarchy or the accessibility contract the component depends on.

Two Primaries side-by-sideThe user can't tell which is the recommended path. Demote one to Secondary or Ghost.

Danger for non-destructive actionsRed is a strong signal — reserve it for irreversible deletions. Save is Primary.

Square cornersAll buttons in this system are pill-shaped. Don't override --radius-pill.

ALL CAPS labelsSentence case only. ALL CAPS is reserved for overlines and labels — not interactive controls.

Hit areas under 24pxBelow the XS minimum, buttons fail touch targets. Always pick a defined size.

Two trailing-meaningful iconsPick one — leading reinforces meaning, trailing hints at progression. Never both.

10For agents

Rules an agent can apply without judgement. Each anti-pattern below is a real failure seen in consuming code, with the reason it fails rather than a bare prohibition.

Anti-patterns

What to avoid, and what breaks when you do it.

avoid
Anti-patternWhy it fails
Two or more primary in one viewPrimary means "this is the action". Two of them means neither is, and the user has to read both labels to decide — which is the work the variant was supposed to do.
iconOnly without aria-labelThere is no text node, so the button has no accessible name. A screen reader announces "button" and nothing else. This is why iconOnly is a prop and not a bare class.
danger as the default action in a dialogDestruction should require intent. Making it the default means Enter destroys data.
A button that navigatesBreaks middle-click, copy-link, back and open-in-new-tab. Use <a class="btn btn-link"> when it should look like a button but go somewhere.
Mixed variants inside ButtonGroupThe group overlaps borders by one hairline so the row reads as a single control. Different variants break the shared border and it reads as three loose buttons.
Hardcoding height, radius or borderThe button reads --control-h-*, --radius-pill and --border-hairline. A literal detaches it from the control scale, so it stops lining up with inputs and selects beside it.
disabled with no explanationA dead control with no reason is a dead end. State why nearby, or keep it enabled and explain on submit.
loading without keeping the labelSwapping the label for a spinner erases what is happening. loading keeps the label and locks the width, so the row does not reflow.

Rules for agents

Apply in order.

rules
1Decide the element first: commits in place → Button; navigates → <a>; holds a value → Switch / ToggleChip / Combobox.
2Count the primaries in the view. If more than one, demote all but the committing action to secondary.
3If the button has no visible text, set iconOnly and write aria-label as a verb phrase — "Delete row", not "Trash".
4Never set height, border-radius, font-size or colour on .btn. Pick a size and a variant; those are the only two axes.
5On a dark surface use onInverse, not a colour override — the inverse layer keeps navy text on the white fill in both themes.
6For an async action, drive loading from the request state; do not also set disabled (loading already blocks the click).

11Behaviour & contract

What the component does for you, and what remains yours. The split matters: consuming the CSS alone gives you appearance, not behaviour.

Ships in Button.tsx

Present whichever way you consume it — these live in CSS or in the element itself.

shipped
Focus ring:focus-visible only, so a mouse click leaves no ring while keyboard focus is always visible.
Disabled handlingThe native attribute blocks click, submit and focus; the CSS drops opacity and sets cursor: not-allowed.
LoadingSpinner replaces the leading icon, label stays, width locks — no reflow mid-request. Sets aria-busy and blocks the click.
Icon sizingIcons inherit from --icon-* per size, so a 24px button never gets an 18px glyph.
Square lockiconOnly ties width to height at every size — the button cannot go oblong.
Group geometryButtonGroup collapses inner radii and overlaps borders by one hairline; it also sets role="group".

You must implement

The component cannot know these.

yours
aria-label on iconOnlyRequired. A verb phrase naming the action.
aria-label on ButtonGroupRequired — names the cluster: "View mode", "Alignment".
One variant per groupThe component does not police its children.
Loading stateYou own the flag; the button only renders it.
Confirmation for destructiondanger is a colour, not a guard. Add the dialog.
Why a button is disabledNearby text, tooltip, or validation on submit.

Vocabulary

reference
ClassPurpose
.btnBase — every button starts here. Sets the 40px box, hairline border, pill radius, focus ring and disabled handling.
.btn-primaryBrand fill — the one committing action per view.
.btn-secondaryNeutral outline — the alternative to primary; safe to repeat.
.btn-tertiarySubtle tonal fill — dense toolbars where an outline would add too many lines.
