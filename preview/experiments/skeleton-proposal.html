Skeleton

Hoje o shimmer só existe dentro da tabela (.dt-skeleton). A proposta é um Skeleton avulso com três formas — linha de texto, círculo e retângulo — para cards e listas. A regra que importa: o esqueleto tem o mesmo formato do conteúdo que vem, para nada pular quando os dados chegam.

API

<Skeleton shape="text"   width="70%" />        // uma linha; altura vem da fonte do pai
<Skeleton shape="text"   lines={3} />          // parágrafo; a última linha termina curta
<Skeleton shape="circle" size={32} />          // avatar, ícone
<Skeleton shape="rect"   width={120} height={32} />  // botão, imagem, gráfico

<SkeletonGroup label="Carregando transações">   // aria-busy + o rótulo só para leitor de tela
  …
</SkeletonGroup>

Esqueleto ao lado do conteúdo real

Troque entre os dois: o card e a lista não mudam de altura nem de posição quando os dados chegam. A regra para isso: cada linha de texto do esqueleto ocupa a altura de uma linha real (a barra tem a altura-x e o resto é margem), e o número de linhas é o do conteúdo típico — aqui, um parágrafo de duas linhas.

O que muda

Arquivos: primitives.css (o .skeleton e as três formas, com um keyframe só), components/Skeleton/ (.tsx, .d.ts e bancada), preview/skeleton.html, entradas no catálogo, no índice e no README. O .dt-skeleton da tabela passa a usar o mesmo keyframe, então os dois shimmers ficam idênticos. A página Motion aponta para o componente.

Acessibilidade: as formas são aria-hidden; o grupo tem aria-busy="true" e um rótulo só para leitor de tela, que é o que se anuncia. Sem animação quando o sistema pede movimento reduzido.
